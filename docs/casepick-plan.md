# 拾例（CasePick）PRD：Harness 内的个人评测集

## 1. 定位与目标

面向 Agent / Harness 开发者及日常用户，在 deepseek-harness、Pi 的使用过程中低侵入地积累个人评测集，并在原 Harness 内低成本完成评测。

解决两个问题：用户缺少时间主动整理案例；通用评测无法充分回答“这个模型或配置是否适合我的任务，会不会重复犯我在意的错误”。

核心价值：**正常使用即可积累，需要时即可评测。** 无感指不增加日常操作负担，不代表隐瞒采集、外发或费用。

## 2. 核心体验

1. 用户正常使用 Harness；插件后台捕捉纠正、约束违背和失败信号，不阻塞对话、不逐次弹窗。用户也可随手指定“把这次记为案例”。
2. 插件异步提取、归因、去重。依据充分的案例自动纳入评测集；有歧义的保留为候选，在用户查看或发起评测时集中确认。
3. 用户在当前 Harness 内选择模型或配置发起评测，无需手动搬运上下文、编写脚本或进入独立平台。
4. 结果回到当前界面，展示通过、失败、无法判定及证据；与历史结果可比时，展示修复项和新增失败。

## 3. 功能需求

| 能力 | 产品要求 |
| --- | --- |
| Harness 接入 | 接入会话、指令和工具调用数据；支持自动发现与显式标记；后台处理不影响正常交互，采集异常可察觉。 |
| 候选发现与归因 | 区分既有要求被违背、需求补充、目标变化和环境故障；纠正只是候选信号，用户沉默不代表成功。 |
| 案例构建 | 保存待测输入、必要上下文、期望行为、评分规则、来源证据及环境前置条件；长会话不默认整体复制。 |
| 评测集维护 | 区分候选与可评测案例，记录自动纳入或人工确认依据；支持修正、移除、去重和批量确认，避免逐条审核成为必经步骤。 |
| 原生评测 | 在 Harness 内发起并接收结果；提供低成本快速检查和按需完整重放，明确各自覆盖范围及证据强度。 |
| 判分与对比 | 优先使用确定性规则，必要时使用评审模型；保留判分证据，区分行为失败、环境失败和无法判定，支持可比运行之间的回归对比。 |
| 数据控制 | 默认本地保存；支持暂停采集、查看、删除和 JSONL 导出；采集范围、模型调用及费用策略对用户可见。 |

## 4. 质量、成本与安全边界

### 案例可信

- 期望行为必须能由待测时已知的要求支持；不得将后续新增要求追溯为先前错误，也不得将后续纠正或答案泄漏到输入。
- 不直接将模型回答当标准答案。自动纳入需有明确要求、失败证据和可检查标准；仅有模型自报置信度不足以纳入。
- 对案例检查“已知错误应失败、经确认的正确行为应通过”；评审模型参与时，避免生成与判分相互自证。
- 首期聚焦真实失败与约束违背；后续纳入具有可验证成功标准的常见任务，避免将纯失败集合宣称为全面的个人能力评测。

### 成本可控

- 采集轻量化，提取异步化；不对每条消息调用模型。后台处理和评测均受可配置预算约束。
- 默认选取去重后的小规模代表集，允许完整评测；运行前展示范围和预计消耗，支持取消，达到预算上限时停止新增工作并标记未完成项。
- 优先规则判分，必要时再用模型；按需重复运行以复核不稳定结果，不把单次通过宣称为稳定修复。

### 重放与隐私

- 交互留在当前 Harness，重放使用隔离会话与环境，不继承已经看过纠正的当前上下文；默认禁止有外部副作用的操作。
- 明确区分对录制轨迹的检查与实际重新执行；环境无法恢复时标记不可重放，不计作模型失败。
- 结果绑定案例、模型、Harness 配置和评分规则版本，记录环境、运行参数及重复次数；比较时保持非待比较因素一致，并展示实际成功/失败次数。
- 默认不向外部服务发送会话内容；包括片段、工具输出在内的外发须授权。敏感数据处理覆盖存储、来源、导出及评分请求；脱敏破坏语义的案例不得静默纳入。

## 5. 范围与分期

1. **单 Harness 闭环：** 从 deepseek-harness 或 Pi 中选择一个，覆盖真实纠正 → 自动构建与必要确认 → 本地保存 → 隔离评测 → 原界面反馈。首期必须包含基本去重、预算控制和数据控制，不能只完成采集。
2. **扩展与对比：** 接入第二个 Harness，完善跨来源去重、批量维护、JSONL 导出及模型 / 配置回归对比。
3. **代表性增强：** 在可信失败案例之外，补充常见任务；优化案例选择与评测成本。

不做独立评测平台、通用排行榜或自主修改 Harness 的修复系统；不追求首期覆盖所有任务类型。具体接入机制、存储结构和重放方案由技术设计确定。

## 6. 验收与效果指标

- **低侵入：** 正常会话不等待提取或评测，不要求逐条确认；后台失败不影响对话，用户可暂停采集并删除数据。
- **案例有效：** 用真实纠正、需求补充、目标变化和环境故障样本验证归因；纳入案例可追溯、无答案泄漏，评分规则能够区分经确认的正反例。
- **端到端：** 在首个 Harness 内展示真实失败案例的积累、重放和修正前后验证；记录运行次数与不稳定结果。第二阶段在另一个 Harness 中同样完成闭环。
- **成本受控：** 验证预算上限、取消与部分完成提示；报告实际耗时和调用消耗，不隐瞒快速检查未覆盖的内容。
- **价值可量化：** 记录每周人工维护时间、案例无需修改即可使用的比例、环境可重放比例、原错误复现情况、单次评测耗时与成本，以及确认发现的回归。指标口径在试点前固定，目标值依据试点基线确定。
